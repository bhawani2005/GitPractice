About Spring Core

Spring Core provides the foundation for building flexible Java applications through Inversion of Control and Dependency Injection.

What is Spring Core?

Spring Core is the foundational part of the Spring Framework. It helps applications create, configure, and connect objects, reducing hard-coded dependencies and making code easier to change and test.

Its central principles are Loose Coupling, Separation of Concerns, and reusable application components.

Inversion of Control and Dependency Injection

Inversion of Control (IoC) means that object creation and dependency management are handled by the framework rather than directly by application classes. Dependency Injection (DI) is the technique Spring uses to provide an object's required dependencies.

  • Constructor Injection makes required dependencies explicit and supports immutable objects.
  • Setter Injection is useful for optional dependencies or later configuration.
  • Constructor injection is generally preferred for required dependencies.
Instead of a class constructing every collaborator itself, it receives those collaborators from the Spring container.

The IoC Container and Beans

The Spring IoC Container creates and manages application objects called Beans. Bean definitions can be discovered from components or declared in configuration.

  • BeanFactory provides basic bean management.
  • ApplicationContext builds on it with features such as events, resource loading, and integration support.
  • @Component, @Service, and @Repository mark classes for component scanning.
  • @Configuration and @Bean declare beans using Java configuration.

Configuration and Autowiring

Spring supports XML Configuration, Annotation Configuration, and Java Configuration. Component Scanning finds annotated classes and registers them as beans.

  • @Autowired injects a matching dependency.
  • @Qualifier identifies which bean to use when several candidates match.
  • @Primary marks the preferred candidate.
  • @Value injects a configured property value.
  • @PropertySource loads values from a properties file.

Bean Lifecycle and Scopes

The container creates a bean, injects its dependencies, runs initialization callbacks, and eventually performs cleanup. @PostConstruct and @PreDestroy can mark initialization and destruction methods.

A bean's Scope controls how instances are created and shared:

  • Singleton Scope is the default: one instance per container.
  • Prototype Scope creates a new instance when requested.
  • Request Scope and Session Scope apply to web requests and sessions.

Other Core Features

  • BeanPostProcessor can customize beans before and after initialization.
  • Lazy Initialization delays bean creation until it is first needed.
  • Application Events allow components to publish and listen for notifications.
  • Aspect-Oriented Programming (AOP) separates cross-cutting behavior such as logging and security from core business logic.
  • Spring Expression Language (SpEL) evaluates expressions in configuration and application contexts.

Why Spring Core Matters

Understanding Spring Core helps developers build modular, maintainable, and testable applications. By letting the container manage dependencies and bean lifecycles, application code can focus on business behavior instead of manual object wiring.
